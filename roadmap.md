# zuspin roadmap

Goal: vendor [libspin](https://github.com/pedrobtz/libspin), the library form of the Spin model
checker, into an R package that installs from source on Linux, macOS and Windows with R's own
toolchain, and expose parsing, verifier generation, LTL translation and simulation to R.

The C-side work (removing `exit()`, redirecting output, resetting globals) is **libspin's**
roadmap, not this one. Stages here depend on libspin stages as noted; do not start a stage whose
dependency is not tagged.

## What we are vendoring

| Property | Value | Consequence for us |
| --- | --- | --- |
| License | BSD 3-Clause | Compatible with MIT; `LICENSE.note` names Spin's copyright, authors as `cph`/`ctb` |
| Language | C99, no external dependencies | No `configure`, no `SystemRequirements`; the lowest-risk vendoring in the family |
| Parser | yacc grammar; libspin commits the bison output | Vendor the generated `y.tab.c`, never run bison at install |
| Build | plain make, object list from libspin's `tools/objects.sh` | `src/Makevars` lists objects explicitly, generated by our vendor script |
| Output | callbacks (libspin Stage 2) | The shim writes to `Rprintf`/`REprintf`, or captures into a character vector |
| Files | `pan.*` under a `workdir` | Always a fresh `tempfile()` directory unless the user passes one |
| Preprocessing | not in the library | Done from R with the C compiler R was built with (Stage 4), or skipped |
| Threading | one instance at a time, sequential calls | Matches R; a single context lives for the package's lifetime |

## Stage 0 — Package identity and API decision

- Fill `DESCRIPTION`: Title, Description, `Authors@R` (Gerard J. Holzmann as `cph`, `ctb`),
  `SystemRequirements: C99` is not needed; add `URL`/`BugReports`.
- Public R API, smallest first:
  - `spin_parse(path, ...)` → diagnostics and symbol table as a tibble-free data frame
  - `spin_generate(path, dir = tempfile(), separate = NULL)` → paths of `pan.*`
  - `spin_ltl(formula, name = NULL)` → never claim as a character string
  - `spin_simulate(path, seed = NULL, max_steps = NULL, trail = NULL)` → captured output as
    lines, plus the exit status
  - `spin_verify()` (Stage 5) → generate, compile with R's C compiler, run `pan`, parse the
    report
- No preprocessing in Stage 0–3: `#include`/`#define` in a model is an error with a clear
  message until Stage 4.

Exit: `DESCRIPTION` is real; this list is copied into `CLAUDE.md` as the contract.

## Stage 1 — Toolchain spike (no Spin yet) — depends on nothing

Prove the shape before importing 26k lines: a `src/` with one vendored-style C file compiled
from an explicit object list, an `init.c` with `R_registerRoutines`, and a `spin_toolchain()`
that reports the compiler and `__STDC_VERSION__`. Run the full CI matrix including Windows and
the r-devel containers. This is cheap for C99, and it establishes the `Makevars` conventions:
portable make, hand-listed objects, no `Makevars.win`, `-D__USE_MINGW_ANSI_STDIO=1`.

Exit: green matrix on an empty shell.

## Stage 2 — Vendor libspin — depends on libspin `v0.1.0` (its Stage 4)

- `tools/vendor.sh`: clone the pinned tag, copy `Src/` (library objects only, no CLI) to
  `src/libspin/`, copy `include/spin.h`, record version/commit/date and per-file checksums in
  `tools/vendor/`, regenerate the object list in `src/Makevars` from libspin's
  `tools/objects.sh`. Idempotent: delete and rebuild, `git status` must be clean on re-run.
- `tools/vendor/verify` and a `vendor.yml` workflow that fail when the vendored tree differs
  from upstream-at-tag plus our patches.
- Patches, if any, live in `tools/patches/` and are reapplied by the script. Expected to be
  empty: anything R needs should be a libspin feature, not a zuspin patch.
- `LICENSE.note`, `inst/COPYRIGHTS` if R CMD check asks.

Exit: `R CMD INSTALL` builds the whole library into `zuspin.so`; `spin_version()` returns
libspin's string.

## Stage 3 — The shim — depends on Stage 2

- `src/shim.c`: one static `spin_ctx *` created at load (`R_init_zuspin`), destroyed at
  unload. Sinks write through `Rprintf`/`REprintf`, or into a growable buffer when the R call
  asked for capture.
- Error firewall: every `.Call` runs the libspin action, **then** cleans up, **then** raises
  with `Rf_error` from a message copied out of the context. Nothing may `Rf_error` while a
  libspin frame is on the stack; the arena would survive the `longjmp`.
- Interrupts: pass an `interrupt` callback (libspin Stage 5) that checks
  `R_CheckUserInterrupt` without letting it jump, via `R_ToplevelExec`; return non-zero so
  libspin unwinds through `spin_bail()`.
- Strings crossing the boundary are declared UTF-8: `Rf_translateCharUTF8()` in,
  `Rf_mkCharCE(…, CE_UTF8)` out. Promela identifiers are ASCII, but `printf` strings and
  file paths are not guaranteed to be.
- `spin_parse`, `spin_generate`, `spin_ltl`, `spin_simulate` as above, with testthat tests over
  a handful of `Examples/*.pml` copied into `inst/extdata/` (license allows it).

Exit: the four functions work on macOS, Linux and Windows CI; a test calls each twice and
compares results.

## Stage 4 — Preprocessing from R — depends on Stage 3

- `spin_preprocess(path, defines = character())` runs the C preprocessor R was configured with
  (`R CMD config CC` plus `-E -x c`), via `processx`/`system2`, into a temp file that the
  library then reads. On Windows this is Rtools' gcc, which every user installing from source
  already has.
- `preprocess = TRUE` default on the four functions; `FALSE` is the fast path.

Exit: models with `#include` and `#define` work; the preprocessor command is visible in a
verbose option for debugging.

## Stage 5 — Verification workflow — depends on Stage 4

- `spin_verify(path, dir, options = spin_pan_options(...))`: generate `pan.c`, compile with the
  same compiler as Stage 4 and the `-D` flags from the options (`SAFETY`, `BITSTATE`,
  `COLLAPSE`, `NP`, …), run `./pan` with runtime flags, capture and parse the report (errors,
  states, memory, depth) into a list, and keep the trail file when there is one.
- `spin_trail(path, trail)` replays through `spin_simulate(trail = )`.
- This stage is pure R plus `processx`; nothing in C. Cross-platform differences are in
  executable suffix and quoting.

Exit: `spin_verify()` on `peterson.pml` reports no errors; on a model with a deliberate
assertion violation it returns the trail and `spin_trail()` shows the counterexample.

## Stage 6 — Hardening — depends on Stage 3

ASan/UBSan builds in CI (`R CMD INSTALL --configure-args` is not available, so use
`~/.R/Makevars` on the sanitizer leg), valgrind on Linux, `gctorture(TRUE)` through the test
suite, rchk container, `covr`. Repeated calls in one session, failure followed by success,
interrupts in a long simulation, UTF-8 paths.

## Stage 7 — Documentation

README with a worked verify-and-replay example, a vignette on Promela from R, pkgdown
reference grouped by parse/generate/verify/simulate, `NEWS.md`. State plainly that the
library is sequential, not concurrent.

## Stage 8 — CRAN

`cran-extrachecks`, `cran-comments.md`, spell check, URL check, the `inst/COPYRIGHTS`
question, no writing outside `tempdir()` in examples or tests.

## Deferred, decided

- **In-process `pan`.** `pan.c` is a program with its own globals and `exit()` calls; running
  it in-process would mean doing to it everything libspin did to Spin. Out of scope.
- **A term/AST API over Spin's `Lextok`.** Interesting, but the AST is mutated by generation
  and has no stable upstream contract. Not before 1.0.
